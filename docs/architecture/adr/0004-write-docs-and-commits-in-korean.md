# 문서와 커밋 메시지를 한국어로 쓴다

## 맥락과 문제

결정 당시 이 저장소의 언어는 대상마다 섞여 있었다. 문서와 코드 주석은 한국어였지만, 커밋 제목은 대부분 영어였고 PR 본문은 한국어(#10)와 영어(#8)가 섞여 있었다. 에이전트는 최근에 본 예시를 따라 언어를 고르므로, 기준이 없으면 같은 저장소에서도 에이전트마다 다른 언어로 쓴다. 저장소에 남는 글을 어떤 언어로 쓸 것인가?

## 판단 기준

- 저장소 소유자가 가장 빨리 읽을 수 있어야 한다
- 에이전트가 고민 없이 따를 수 있게 대상마다 언어가 하나로 정해져야 한다

## 검토한 선택지

- 문서와 커밋 메시지를 모두 한국어로 쓴다
- 모두 영어로 쓴다
- 문서는 한국어, 커밋 메시지는 영어로 쓴다

## 결정

"문서와 커밋 메시지를 모두 한국어로 쓴다"를 선택한다. 저장소 소유자가 정했다. 다음은 영어로 둔다.

- Conventional Commits의 `type`과 `scope` 키워드
- 스크립트가 출력하는 메시지
- 식별자, 명령, 경로, 도구 이름

세부 규칙은 [글쓰기 규칙](../../standards/writing-style.md)과 [커밋 규칙](../../standards/commit-convention.md)에 있다.

### 결과

- 장점: 저장소에 남는 글의 언어가 대상마다 하나로 정해진다
- 단점: `git log`에 영어 제목과 한국어 제목이 섞인다. 예전 커밋은 고치지 않는다
- 단점: 한국어를 읽지 못하는 사람과 도구는 커밋 기록을 읽기 어렵다

### 확인 방법

리뷰에서 커밋 메시지, PR, 문서의 언어를 확인한다.
