# 에이전트 작업 절차

어떤 에이전트와 모델이 작업해도 같은 순서로 일하고 같은 기준에서 멈추도록 작업 절차를 정한다.

## 시작

1. `AGENTS.md`의 [작업별 문서](../../AGENTS.md#작업별-문서) 표에서 읽을 문서를 찾는다. 표에 없으면 고칠 파일 경로를 각 문서의 `scope`와 비교한다.
2. 고칠 파일과 함께 바뀌어야 하는 곳을 확인한다. 각 규칙 문서의 "함께 고칠 곳"을 따른다.
3. 오류나 이상 동작을 조사하는 작업이면 [찾기](issues.md#찾기)에 따라 같은 사례의 이슈를 먼저 찾는다.
4. 요청이 모호하거나 규칙끼리 충돌하면 추측하지 않고 사용자에게 묻는다.

## 사용자 확인이 필요한 행동

다음은 사용자가 요청했거나 확인한 경우에만 한다. 머신 상태를 바꾸거나, 외부에 보이거나, 되돌리기 어려운 행동이다.

- `install.ps1`, `install.sh` 실행. 패키지를 설치하거나 업그레이드하고 홈 디렉터리 설정을 바꾼다. 설치를 요청받으면 [INSTALL.md](../../INSTALL.md)를 따른다
- `config/macos/.macos` 실행. macOS 시스템 설정을 바꾸고 Finder와 Dock을 재시작한다
- 패키지 매니저로 하는 설치와 삭제(`winget`, `brew`, `apt-get`, `npm install -g`)
- 홈 디렉터리에 배포된 설정 파일(`~/.claude/settings.json` 등)을 직접 고치는 일
- 커밋, push, PR 생성과 병합, 원격 브랜치 삭제
- 이슈 생성, 댓글, 이슈의 라벨 변경(triage 포함), 닫기와 GitHub 라벨 정의의 생성, 변경
- git 기록을 바꾸는 명령(`rebase`, `reset --hard`, `push --force`)
- 에이전트 권한과 샌드박스를 넓히는 설정 변경. 기준은 [권한과 정책](../../SECURITY.md#권한과-정책)에 있다

## 저장소 파일과 배포된 사본

저장소가 관리하는 설정은 저장소 파일을 고친다. 홈 디렉터리의 사본만 고치면, 덮어쓰기 대상은 다음 install에서 저장소 내용으로 돌아가고, 병합 대상은 저장소와 어긋난 채 남는다. 배포 방식은 [배포 방식](../../ARCHITECTURE.md#배포-방식)에 있다.

## 검증

- 파일을 바꿨으면 끝내기 전에 CI 설정(`.github/workflows/lint.yml`)의 각 단계 명령을 로컬에서 그대로 실행한다. 바꾼 파일 종류에 해당하는 단계만 실행해도 된다. PowerShell 구문 단계는 `pwsh`에서 실행한다.
- `git ls-files`는 git에 추가하지 않은 새 파일을 나열하지 않는다. 새 파일은 경로를 직접 넘겨 검사한다.
- CI는 설치 동작을 확인하지 않는다. 설치 동작을 바꿨으면 실제로 실행해 확인한 OS와 확인하지 못한 OS를 구분해 보고한다.
- 검사 도구가 없어 실행하지 못했으면 그 사실을 보고한다. 실행하지 않은 검사를 통과했다고 쓰지 않는다.

## 문서와 코드가 다를 때

- 동작을 설명하는 문서(`ARCHITECTURE.md`, `Playbook`, `Reference`)가 코드와 다르면 코드를 사실로 본다. 문서를 고치는 변경을 함께 하거나, 작업 범위 밖이면 사용자에게 보고한다.
- 규칙 문서(`Standard`)와 코드가 다르면 어느 쪽이 맞는지 사용자에게 확인한다. 임의로 한쪽을 고치지 않는다. 그 규칙 문서가 사람의 검토를 거치지 않았으면([generated와 verified](metadata.md#generated와-verified)) 그 사실도 함께 알린다.
- 문서에 없는 상황에서는 주변 코드의 관례를 따른다. 새 관례를 만들었으면 보고에 적고, 문서로 남길지 사용자에게 묻는다.

## 보고

작업을 마치면 다음 순서로 짧게 보고한다.

1. 결과: 요청한 작업을 끝냈는지
2. 바꾼 파일과 내용
3. 실행한 검증과 그 결과
4. 확인하지 못한 것(실행하지 못한 OS, 실행하지 않은 검사)과 남은 위험

보고와 질문은 한국어 `~합니다`체로 쓴다. 대화는 저장소에 남는 글이 아니므로 문서의 `~한다`체를 쓰지 않지만, [글쓰기 규칙](writing-style.md)의 나머지 규칙은 그대로 따른다.

## 검사

자동 검사는 없다. 리뷰에서 확인한다.
