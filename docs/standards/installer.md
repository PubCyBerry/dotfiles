# 설치 스크립트

`install.ps1`과 `install.sh`를 고칠 때 지키는 규칙이다. 설치 단계와 배포 방식의 동작은 [ARCHITECTURE.md](../../ARCHITECTURE.md)에 있다.

## 범위

- install은 패키지 매니저, 공식 installer, 각 도구의 `update` 명령을 부르고 설정 파일을 배포하는 일만 한다.
- 설치 기록(receipt), 백업, uninstall 스크립트, 설치 후 검증 스크립트를 두지 않는다. 지울 때는 패키지 매니저와 각 도구의 방법을 쓴다. 이유는 [ADR 0005](../architecture/adr/0005-keep-installers-thin.md)에 있다.
- 이 범위를 넘는 기능이 필요하면 먼저 ADR을 `status: draft`로 제안한다.

## 단계

- `install.ps1`과 `install.sh`는 같은 단계를 같은 순서로 실행한다. 단계를 추가하거나 순서를 바꾸면 모든 install 스크립트를 함께 고친다.
- 새 단계는 각 스크립트 앞부분에 정의된 헬퍼 함수를 쓴다. 매니페스트를 직접 파싱하거나 파일을 직접 복사하지 않는다. 헬퍼가 주석 제거, 실패 기록, 파일 인코딩을 처리한다.

## 여러 번 실행

- 몇 번을 실행해도 결과가 같아야 한다. 이미 있으면 건너뛰거나 최신으로 올린다.
- 사용자가 넣은 설정 값을 지우지 않는다. 사용자가 고칠 수 있는 파일은 병합이나 마커 블록으로 배포한다.
- 공식 installer로 설치하는 도구는 없으면 공식 installer로 설치하고, 있으면 그 도구의 `update` 명령으로 최신을 맞춘다. 도구가 스스로 업데이트한다고 보고 건너뛰면, 스스로 업데이트하지 않는 도구는 처음 설치한 버전에 머문다(#11).
- 공식 installer로 설치할 도구를 추가하면, 그 도구의 `update` 명령이 입력을 기다리지 않고 끝나는지와 이미 최신일 때 종료 코드 0을 내는지 확인한다. install은 사용자 입력 없이 진행되어야 하고, 0이 아닌 종료 코드는 실패로 기록된다.

## 실패 처리

- 단계 하나가 실패해도 다음 단계를 계속한다. 실패는 실패 기록 헬퍼로 남기고, 마지막에 모아 보여 준 뒤 종료 코드 1로 끝낸다.
- 바로 종료하는 경우는 이후 단계를 진행할 수 없는 전제 조건이 없을 때뿐이다(macOS의 Homebrew).

## 배포 방식 선택

새 설정 파일은 아래 기준으로 배포 방식을 고른다. 각 방식의 동작은 [배포 방식](../../ARCHITECTURE.md#배포-방식)에 있다.

| 조건 | 방식 |
|---|---|
| 앱이나 다른 도구가 실행 중에 고쳐 쓰는 JSON 또는 TOML 파일 | 병합 |
| 사용자가 직접 내용을 덧붙이는 셸 프로파일 | 마커 블록 |
| 저장소가 내용 전체를 소유하는 그 밖의 파일 | 덮어쓰기 |

덮어쓰기 대상에서 사용자가 고친 내용은 다음 install에서 사라진다. 백업하지 않으므로, 사용자가 고칠 수 있는 파일은 덮어쓰기로 배포하지 않는다.

## 병합 대상 파일

병합은 jq(JSON)와 yq(TOML)로 하고, 겹치는 키는 기존 값이 이긴다. 이유는 [ADR 0006](../architecture/adr/0006-merge-app-managed-config.md)에 있다.

- 저장소에서 기존 키의 값을 바꾸면 기존 머신에는 반영되지 않는다. 반영해야 하면 커밋 본문에 "대상 파일에서 그 키를 지우고 install을 다시 실행한다"는 조치를 쓴다.
- TOML 설정 파일에 주석을 두지 않는다. yq 병합이 주석을 매번 다시 붙인다.
- TOML 문자열에 Windows 경로를 쓸 때는 백슬래시 대신 슬래시를 쓴다(`config/herdr/config.windows.toml`). yq의 TOML 인코더가 `\b`를 백스페이스로 바꾼다.
